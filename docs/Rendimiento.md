# Performance

How *Sins of the Fallen Empires* runs on a modest PC, and the performance mods that ship in the pack. Sprint plan in [Sprints.md](Sprints.md); technical design in [Arquitectura.md](Arquitectura.md).

## Target PC

The pack must run well on this PC, the minimum it is built for:

| Part | Minimum |
|------|---------|
| CPU | AMD Ryzen 3 3200G (4 cores, 4 threads) |
| GPU | NVIDIA GTX 1650 (4 GB) |
| RAM | 8 GB DDR4 |
| Disk | 512 GB SATA SSD |

Goal: 60 fps or more in the capitals at render distance 10, and no stutter from memory.

With 4 cores the CPU is the limit, not the GPU: Minecraft builds chunk meshes and ticks the world on the CPU. With 8 GB, the game cannot take more than half without starving Windows.

## The performance mods

All of them are client or server optimizations with no content of their own, for Forge 1.20.1, from Modrinth. Versions are pinned in `gradle.properties` (as Modrinth version ids).

| Mod | Version | What it does | Side |
|-----|---------|--------------|------|
| **Embeddium** | 0.3.31 | Rewrites chunk rendering (the Forge port of Sodium): the biggest frame-rate gain | Client |
| **Entity Culling** | 1.11.2 | Skips entities and block entities behind walls: the capitals' statues, banners, chests and NPCs | Client |
| **ImmediatelyFast** | 1.5.5 | Batches HUD, text and map drawing: the mod's HUD, boss bars and dialogue boxes | Client |
| **ModernFix** | 5.27.85 | Faster loading, much less memory for models and registries | Both |
| **FerriteCore** | 6.0.1 | Less memory for block states and models | Both |
| **Canary** | 0.3.3 | Server tick optimizations (the Forge port of Lithium): AI, collisions, block ticks | Both |
| **Saturn** | 0.1.3 | Fewer memory allocations | Both |
| **Memory Leak Fix** | 1.1.5 | Fixes vanilla and Forge memory leaks | Both |
| **Dynamic FPS** | 3.11.4 | Lowers the frame rate when the window is in the background or the game is idle | Client |

Left out on purpose:

- **Oculus** (shaders): too heavy for a GTX 1650 with this many custom models.
- **Ksyxis** and **Noisium**: they change world loading and noise generation; the world of Aetheris is generated by the mod's own map and builders, and the gain is not worth the risk.

### Pack configuration

`pack/config/` holds the config files the pack ships. A Gradle task copies them to `run/config` before every `runClient`, `runServer` and `runGameTestServer`, so development runs as the pack does.

- `modernfix-mixins.properties`: `mixin.perf.remove_spawn_chunks=false`. ModernFix unloads the spawn chunks by default. The mod's places, NPCs and GameTests are made for vanilla, where Sulthari (at spawn) stays loaded. With the option on, two skill GameTests failed: the zombie in the test sat in a chunk that was not ticking, so the Sorceress's bolt could not find it.

## Launcher settings

**Memory: 4 GB** (`-Xms4G -Xmx4G`). Not more on a PC with 8 GB: Windows, the launcher and Discord need the rest. Not less than 3 GB.

Java arguments for the launcher:

```text
-Xms4G -Xmx4G -XX:+UseG1GC -XX:+ParallelRefProcEnabled -XX:MaxGCPauseMillis=200
```

**Use the GTX 1650, not the Ryzen's graphics.** The 3200G has its own graphics (Radeon Vega 8). If the monitor is plugged into the motherboard, or Windows picks the wrong GPU, the game runs on the integrated one at a fraction of the speed. Plug the monitor into the GTX 1650, and in *Windows Settings → System → Display → Graphics* set `javaw.exe` to *High performance*. Keep the NVIDIA driver up to date (Embeddium works around old driver bugs, but slower).

## Recommended video settings

What `scripts/pack_check.py` measures with, and what the pack should suggest for the target PC:

| Setting | Value | Why |
|---------|-------|-----|
| Render distance | 10 (8 if fps drop) | Each step adds chunks for the 4 CPU cores to mesh |
| Simulation distance | 6 | Less of the world ticks: mobs, crops, the mod's places |
| Graphics | Fancy | Fast is the fallback if fps drop |
| Max frame rate | Unlimited or 144 | Vsync off unless the screen tears |
| Entity distance | 75% | The capitals have many NPCs and statues |
| Biome blend | 3x3 | 5x5 and up cost CPU when chunks load |
| Particles | Decreased | Boss signatures and skills are heavy on particles |
| Mipmap levels | 2 | |

## Measurements

`scripts/pack_check.py` plays the mod as a player gets it: a real Forge 1.20.1 client (not the development one) with the mod's jar, every mod of the pack and the settings above, 4 GB of memory. It builds places with PlaceShots and writes the frame rate and the memory in use for every screenshot to `placeshots_perf.log`. `--no-perf-mods` runs the same without the performance mods.

Measured on 2026-10-05 on the development PC (not the target PC: an RTX 4060, render distance 10). The numbers compare the two runs; they do not predict the target's frame rate. Memory is a snapshot and moves with the garbage collector.

| Scene | Without the performance mods | With them |
|-------|------------------------------|-----------|
| Aurelion from above | 831 fps, 3.1 GB | 1,592 fps, 1.9 GB |
| Isfaran from above | 1,721 fps, 3.3 GB | 2,598 fps, 1.2 GB |
| Isfaran from its gate | 1,078 fps, 3.4 GB | 1,954 fps, 2.3 GB |
| The bosses in a row | 768 fps, 2.6 GB | 899 fps, 1.1 GB |

- Chunk rendering roughly doubles: the capitals benefit most.
- The bosses gain least: their GeckoLib models are drawn every frame and Embeddium does not touch entity rendering. They are where the mod's own optimization should start (Sprint 8, "Performance optimization").
- The 19 mods load together with no errors; the 102 GameTests pass with the pack's config.

## For developers

- `./gradlew runClient` and `runGameTestServer` load Embeddium, ModernFix, FerriteCore, Canary, Saturn and Memory Leak Fix. Entity Culling, ImmediatelyFast and Dynamic FPS cannot load there: they are built against the production names with no refmap, so their mixins fail in development. `scripts/pack_check.py` is where they are checked.
- `-PnoPerfMods` leaves the performance mods out; `-PnoPerfMods=canary,saturn` leaves out only those (to find which one breaks something).
- The mod has no mixins of its own, so its risk of clashing with these mods is low. When a mod is added to the pack, run the GameTests and `scripts/pack_check.py` with it.
